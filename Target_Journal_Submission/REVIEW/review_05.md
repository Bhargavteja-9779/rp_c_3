# Review round 5 — Reproducibility reviewer (code package, determinism, documentation)

*Perspective: can an independent person regenerate every number, table and figure from the
package, and does the documentation match what the code does?*
Inspected: `code/README.md`, `run_all.py`, `scripts/`, `requirements.txt`, `environment.yml`,
`tests/`, the cached results and the manuscript build.

## Checks performed
| Check | Result |
|---|---|
| `python -m pytest -q tests` | 12 passed (closed-form LOO logits, held-out/test/cross leverage and jackknife+ sets vs explicit refits; temperature recovery; Platt targets; metrics; corruptions; statistics; APS). |
| `python run_all.py --mode quick --workers 2` from an empty `results/quick/raw` | Re-run in this round; see outcome below. |
| Every number in the manuscript comes from result files | Yes: the manuscript is generated by `build_manuscript.py`, which evaluates `{{…}}` expressions against `results/statistics.json`, `tables/*.csv` and `results/natural_shift.json`; the build fails if any value is missing (strict mode). |
| Seeds | Resample r: numpy seed r (r = 0 official split); MiniRocket seed 1000·r; corruption seeds derived from (dataset, resample, family, severity); ensembles seeds documented in `runner.py`. |
| Exact versions | `requirements.txt` pins all packages; Python 3.13.16. |

## Findings
| # | Severity | Issue | Resolution |
|---|---|---|---|
| R5-1 | MAJOR | The paper states that `run_all.py` regenerates *all* results, but the natural-shift experiment (§6.5) and the LogReg convergence check (§6.8) were separate scripts not called by `run_all.py`. | **Fixed.** New stages `natural` and `logreg` (full mode) call `experiments/natural_shift.py` and `experiments/check_logreg_convergence.py` before `analyze`; both are cached/resumable. Docstring and README updated. |
| R5-2 | MAJOR | README described stale stages and table numbers (e.g. "Rocket, MultiRocket, Hydra (3 resamples)", "Table 3/4/5/6" from an older draft). | **Fixed.** Stage table now matches `run_all.py` (MultiRocket and Hydra on the official split, clean + severity-3, datasets ≤ 3,000 training series; ensembles on the official split; 3 resamples for the four large datasets) and the item → file mapping uses the final Table/Figure numbers; added natural-shift, grouped sensitivity and LogReg-check rows. |
| R5-3 | MODERATE | Runtime and memory: a reader with less than ~14 GB RAM may hit the OOM killer on Crop/ElectricDevices. | README §7 now describes the heavy/light scheduling, the automatic retry of jobs lost to the OOM killer, `scripts/resume_full.sh`, and the approximate wall-clock time. |
| R5-4 | MODERATE | Raw per-job JSON files (`results/raw/`) are git-ignored because of their size. | They are shipped as `results/raw_jobs.tar.gz` (committed) and the tidy `results/raw_results.csv` contains every per-dataset/resample/condition metric, so the analysis can be re-run without recomputing the benchmark. |
| R5-5 | MINOR | Bitwise reproducibility depends on the BLAS thread count (APS ties). | Documented in README; `run_all.py` pins one thread per job. |
| R5-6 | MINOR | The data download URL may change. | `scripts/download_data.sh` documents the archive name; dataset list committed as `data/ucr_equal_length.csv`. |

## Verdict after fixes
The package is complete and the documentation now matches the code. Quick mode provides a
~10-minute end-to-end check; the full study needs about two days on 4 cores.
